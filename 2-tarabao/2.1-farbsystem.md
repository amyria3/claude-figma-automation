# 2.1 Farbsystem und Farbmodi

Figma-Datei „B2C und CI“, Collections `Clrs / Primitives`, `Clrs / Color Modes`, `Clrs / Mega Cards` und `Clrs / Special`

Dieses Kapitel erklärt, wie die Farben im Figma-File zu Themes geschichtet sind, wie Du den Farbmodus in Figma setzt und wie er im Code aussieht.

Klassen stehen immer in zwei Schreibweisen: zuerst die Klasse aus unserem Designsystem (`app.tcss`), dahinter in Klammern die Tailwind-Standardklasse.

---

## What are Themes?

**Grundregel:** Komponenten binden **nur semantische Tokens**, nie palette-direkt (`cole-tint/90`) und nie hardcoded. Sonst folgt das Element dem Theme nicht.
- Das entspricht dem State-Of-Art.
- Das erlaubt mittelfristig einfachere und fehlerfreie Pflege des Designs.
- Das ist die Grundlage fürs erweiterte Theming, kompatibel mit Tailwind.

Das Farbkonzept des B2C-Shops ist im Wesentlichen: Ein **Theme** = eine Kombination aus **Fläche (Surface)** und **Tinte (Tint)**. Ein einziger Umschalter an Frame/Section (Figma) bzw. Container (Code) schaltet Fläche, Text, Icons gemeinsam ins passende Schema. Das Schema der eigenen Komponenten wie z. B. von Buttons schaltet in Figma nicht mit.

**Wichtige Regel für Design**: die Schriftfarbe der Buttons / Primary passt sich in der Regel der surface-Farbe an, auch wenn die Tinte variiert. Hat eine Komponente den Modus cole-tint-surface-snow, so sollte der Button cole-tint-surface-snow oder aber purple-tint-surface-snow haben. Der optische Effekt, der dadurch entsteht, ist einer der wichtigsten ästhetischen Pfeiler des Design-Systems. :)

## So sind die Farb-Variablen in Figma geschichtet

Für die meisten Komponenten gilt der folgende Aufbau:

```
Clrs / Primitives             → Rohfarben, z.B. cole-tint/90, purple-tint-light/old, snow-white/100
   ↓ aliased
Clrs / Color Modes            → 4 Modi (die Schemata)
   ↓ gebunden
Komponenten                   → binden DIREKT die Color-Modes-Tokens
```

Ausgenommen sind die Mega Cards mit ihren Buttons LG sowie Filter und Search. Sie binden eigene Collections:

| Collection | Modi | Nutzung |
|---|---|---|
| `Clrs / Mega Cards` | 4 Kampagnen: `blue-pistacio-green`, `orange-black`, `happy-christmas`, `purple-black` | Cards / MegaCard, Sections / MegaCards, Buttons / LG / … (Karte und Button schalten gemeinsam) |
| `Clrs / Special` | `forest`, `lilac` | Sonderflächen: Cards / VoucherCard (forest), Layout / PromoBar (lilac, Frame-Modus gepinnt) |
| `Clrs / Filter Panel`, `Clrs / Search`, `Clrs / Sustainability Tags`, `Clrs / NutmixerTags` | einer | single-mode, schalten nie mit |

**Token-Namen** tragen die Kategorie im Namen, Muster `<kategorie>-<rolle>-<zustand>`, z. B. `button-primary-bg-default`, `content-text`, `surface-color`. Zustände und die Ableitung der CSS-Namen: [2.6 Design-Tokens §9](2.6-design-tokens-tailwind-v4.md).

## So schaltest Du den Farbmodus

**Umschalten in Figma:** Section/Frame auswählen → Appearance → `Clrs / Color Modes`-Modus setzen.
(!) Eingebettete Komponenten (Überschriften, CMS-Elemente etc.) übernehmen den Modus, wenn er nicht separat gesetzt wurde.

***Insbesondere für Karten- und Karten-ähnliche Elemente wird er stets abweichen, da anderenfalls keine optische Abhebung mittels Hintergrundfarbe stattfinden würde.***

Die Entsprechung der Modus-Schaltung im Code: Die Mutterkomponente trägt ihren Modus, die Tochterkomponente setzt einen eigenen.

```html
<section data-theme="cole-tint-surface-warm" class="bg-surface">                     <!-- Mutterkomponente -->
  <article data-theme="cole-tint-surface-snow" class="bg-surface text-content-text p-lg">…</article>  <!-- Karte hebt sich ab -->
  <!-- (p-7, wenn das Designsystem nicht vollständig aktualisiert worden sein sollte) -->
</section>
```

Den Modus liest Du im Dev Mode unter **Modes** ab: [Einstieg §4](README.md). Code je Modus und die Ausnahmen: [2.3 Dev-Handoff §2–§4](2.3-tailwind-dev-handoff.md).

## Die vier Schemata der Color-Modes (bzw. der Themes)

_'Color-Mode' (Bezeichnung in der Figma-Datei) // 'Theme' in Tailwind_

| Element                | `cole-tint-surface-snow` | `cole-tint-surface-warm` | `purple-tint-surface-snow` | `purple-tint-surface-warm` |
| ---------------------- | ------------------------ | ------------------------ | -------------------------- | -------------------------- |
| Fläche                 | snow-white               | warm-white               | snow-white                 | warm-white                 |
| Tinte (Buttons/Akzent) | cole-tint                | cole-tint                | **purple-tint-light**      | **purple-tint-light**      |
| Input & Fließtext      | cole-tint                | cole-tint                | **purple-tint-dark**       | **purple-tint-dark**       |

### Ästhetische Grundidee hinter den Modi

- **Ausgestanzte Labels** (Label auf gefülltem Button, selektiertes Label) = die **Surface-Farbe** (snow- bzw. warm-white je Modus).
- **Freistehende Icons** und **Buttons / IconButton** werden wie content behandelt und nutzen content-text ('Tint-Konzept').

### Unregelmäßigkeiten

Leichte Unregelmäßigkeit in der Belegung der Werte je nach Theme: **Buttons, Segment, Toggle, laute Headline** nutzen im purple-Theme als Tinte `purple-tint-light`, aber **Inputs und Fließtext** nutzen im purple-Theme als Tinte `purple-tint-dark` (dunkler, lesbarer) — *nicht* dieselbe Tinte wie Buttons.

### Default-Modus

Falls in Figma nicht anders gepinnt:
- Default-Modus für Sections: `cole-tint-surface-warm`.
- Default-Modus für Card: `cole-tint-surface-snow`.

Immer:
- Default-Modus für Nav & Footer: `cole-tint-surface-snow`.

## Geltungsbereich

Alle Komponenten folgen dem Theme (oder sollten es, denn keiner ist frei von Sünde), außer den bewusst ausgenommenen:

- **Mega Cards und Buttons LG** — Kampagnen-Themes in `Clrs / Mega Cards`, gewählt über die Varianten-Property `Variant` an der Komponente.
- **Filter Chips, Search, Filter Panel** — bleiben single-mode.
