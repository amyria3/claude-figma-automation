## 1. Alte Breakpoint-Logik (zuerst angehen)

Diese Sets kodieren Breakpoints noch über eigene Varianten mit Werten wie 1259/1260:

| Set | Property | Vorschlag |
| --- | --- | --- |
| Cards / MegaCard | `Min/Max = min 1260 · max 1259` (Wurzel min-w **1400**, max-w 1259) | auf `Breakpoint = base · md · lg`, rohe Werte raus |
| Sections / MegaCards | `Min/Max = Min 1260 · max 1259` | wie MegaCard |
| Navigation / Header / window-w-min 1260 | `window-w = min 1260` | mit dem Header-Set zusammenführen oder löschen |
| Navigation / Header / window-w-max 1259 | `max-w = max 1259 · 1064 · -` | Property entfernen; die Breite regelt jetzt `flex-col` |
| Components / Cart / CartPage | `window-w = max 1259` | entfernen (nur ein Wert) |
| Components / OverlayComponents / Message | `w-size screen = max w-1259` | entfernen (nur ein Wert) |
| Components / Product / BuyBox, Components / Disclosure | `window-w = Default` | entfernen (nur ein Wert) |

## 2. Sections mit max-w an der Wurzel

`Sections / ProductHeader`, `Sections / Sustainability`, `Sections / Tabs / SectionTabs` (4 Varianten), `Sections / Accordion` (2), `Sections / CMS(CustomSection)`, `Sections / CustomCMS-Section`. Alle haben an der Wurzel ein rohes max-w 1064. Vorschlag: auf das Muster von `Templates / Section` umstellen (Wurzel volle Breite, Kind `wrapper-max-w`).

## 3. min-w über 320 im Modus base

`Components / Account / DataBlock` (4 Varianten, min-w `[twuc]-96` = 384) und die Instanzen darin in `Sections / Account / CollapsibleSection`. Vorschlag: an `Block Element/min-w` binden, das im Modus base auf `min-w-content` (320) zeigt.

## 4. Rohe Werte, die einem Token entsprechen

Diese Werte passen genau zu einer vorhandenen Width-Variable und lassen sich ohne sichtbare Änderung binden:

| Wert | Token | Komponenten |

| max 512 | `Block Element/max-w` | Choice, Components / Account / DataBlock, BlockElement, Cart / CartPage, Checkout / Contact, DeliveryAddress, DeliveryMethodRadioGroup, OrderConfirmation, OverlayComponents / Message, Product / BuyBox, Subscription Management, CMS / CustomContentWithText, ContentModules / CTA, Primitives / BulletedList, Sections / Account / Abo, CollapsibleSection, ToggleGroup, Visuals / Product / Image, Cards / DiscoveryCard (IMG) |

| max 328 | `Cards/CompactSize/max-w` | Components / Cancellation / SelectProducts |

Ohne passendes Token: `Components / Search / Input` und `Sections / Search & Filter` (max 600), `Sections / ProductHeader` (max 1022), ReactionCounter/Cart Message (min 14, Icon-Maß, unkritisch).

## 5. Direkt an Primitive gebunden

Am häufigsten `[twuc]-128` (512) als max-w in Cart-, Checkout-, Input- und Radio-Komponenten, dazu `[twuc]-64` (256) als min-w in Cards und `[twuc]-28/-64` in Navigation / Nav und NavBlocks. Vorschlag: `[twuc]-128` → `Block Element/max-w`; für die übrigen Gruppen eigene semantische Tokens (z. B. `Nav/Block/min-w`, `Cards/Small/min-w`) anlegen, damit sie je Modus steuerbar sind.

## 6. Einzelbefund

`Primitives / DefaultParagraph › Var=1, FontSize=LG, min-w=Block Element / SM` hat kein min-w, obwohl der Name es verspricht (149 Instanzen).
