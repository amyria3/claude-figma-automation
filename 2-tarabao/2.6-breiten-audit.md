## Was am 23.09. geändert wurde

184 Grenzen wurden neu gebunden, meist an vorhandene Tokens (`Block Element/max-w` 170×, `max-w-content`, `Cards/DefaultSize/*`, `Cards/CompactSize/max-w`, `Block Element/Inline/min-w`). `Components / Account / DataBlock` hängt jetzt an `Block Element/min-w` und wird damit im Modus base 320 breit.

### Alte Breakpoint-Properties entfernt

- `Navigation / Header / window-w-max 1259` heißt jetzt **`Navigation / Header`**. Die Property `max-w` ist weg, die doppelte Variante „Search, max-w=-“ wurde gelöscht.
- `Navigation / Header / window-w-min 1260` ist als **`_veraltet / …`** markiert. Die einzige Instanz zeigt jetzt auf `Navigation / Header`. Das Set bleibt stehen, weil es veröffentlicht ist.
- `Components / Cart / CartPage` (window-w), `Components / Disclosure` (window-w) und `Components / OverlayComponents / Message` (w-size screen): Die einwertige Property ist entfernt.
- `Components / Product / BuyBox` ist jetzt eine einzelne Komponente statt eines Sets mit der einzigen Variante „window-w=Default“.

### Sections

- `Sections / ProductHeader` und `Sections / Tabs / SectionTabs` (4 Varianten): Die Wurzel läuft über die volle Breite, der Inhalt liegt im Kind „Wrapper [max-w-content]“ (max-w-content, 20 px Rand). Alle Overrides und Slot-Inhalte der Instanzen sind erhalten.
- `Sections / Sustainability`: max-w an der Wurzel entfernt, weil das Section-Template darin den Inhalt schon begrenzt.
- `Sections / Accordion`, `CMS(CustomSection)`, `CustomCMS-Section` haben keinen Hintergrund. Ihr max-w bleibt als Inhaltsgrenze und hängt an `max-w-content` bzw. `Block Element/Double/max-w`.

### Einzelbefund

`Primitives / DefaultParagraph › Var=1, FontSize=LG, min-w=Block Element / SM` hat jetzt das min-w, das der Name verspricht (`Block Element/min-w`). Die 3 Instanzen, die schmaler als 320 sind, stehen jetzt auf `min-w=x-SM`.

## Nachprüfung am 24.09.

Geprüft: alle 186 Komponenten im Hauptbereich (ohne VISUALS und NOTES) und die drei Seiten in PAGES NEW.

### Behoben

- **Ebene `wrapper-max-w` heißt jetzt „Wrapper [max-w-content]“** (9 Master-Ebenen, alle Instanzen folgen). Namensmuster: `Wrapper [klasse]`.
- **`Sections / Tabs / SectionTabs`:** Alle 4 Varianten hatten einen festen base-Pin auf `Lyt scl / Width`. Die Tabs rechneten dadurch auch auf lg-Seiten mit base-Breiten. Pins entfernt.
- **`Pages / ProductPage` › Variante lg:** `Templates / Page` stand auf Fixed 1280 statt Fill. Jetzt Fill, die Variante selbst Fixed 1280 wie base und md. Die Instanz im Frame „Product Page“ steht auf Fill und füllt 1512 px.
- **`Components / Nutmixer`:** 8 Instanzen hingen an der gelöschten Variante „Components / Nutmixer / Item/True“. Getauscht auf das aktuelle Set, `Show Image?` übernommen.
- **Set-Rahmen mit rohem min-w entfernt:** `ContentModules / Basic` (404), `ContentModules / BasicWithDisclosure` (404), `Components / Filter / FilterPanel` (400), `Buttons / XXS / SecondaryButton` (164, an `[twuc]-41`). Das min-w saß am Set-Rahmen und wirkte auf keine Instanz.
- **Frame „Nussmixer“ in PAGES NEW:**
  - Die Page-Instanz trug alte Overrides: Variante base auf einem breiten Frame, `minWidth` direkt an `Breakpoints/lg`, eigene Pins im Header und im Footer.
  - Beim Nutmixer war die Property `Breakpoint` nicht gebunden.
  - Der Header hing am gelöschten Duplikat „Navigation / Header / window-w-max 1259/…“.
  - Jetzt: Variante lg, `minWidth` an `min-w-screen`, Header aus `Navigation / Header` (State=Search), alle eingebetteten Komponenten auf lg.
  - Die Page-Instanz trägt noch einen eigenen lg-Pin (siehe Falle in 2.5, Regel „Keinen Modus an einer Page-Instanz setzen“).

### Offen, braucht eine Entscheidung

- **`Cards / ProductCard / CompactSize`** ist an `Cards/DefaultSize/min-w` · `max-w` (240 · 384) gebunden. Die Tokens `Cards/CompactSize/min-w` · `max-w` (240 · 328) nutzt die Komponente nicht. Umbinden ändert das Maximum von 384 auf 328.
- **Ungenutzte Width-Variablen:** `Cards/CompactSize/min-w` und `Cards/CompactSize/Img/max-w` hängen an keiner Ebene. Entweder CompactSize darauf umbinden oder die Variablen löschen.
- **`Primitives / ProductImg`** in `Cancellation / SelectProducts` und `OrderCancellation` nutzt `Cards/CompactSize/max-w` (328). Für ein Bild wäre `Cards/CompactSize/Img/max-w` (208) naheliegender.
- **`Components / Nutmixer / Item`** hat zwei Properties für dasselbe: die Variante `Show Image?=False` und das Boolean `Show Image?`. Die Variante ist überflüssig.
- **`_veraltet / Navigation / Header (window-w-min 1260)`** ist veröffentlicht und steht noch im File.
- **25 Textebenen** (Cart / Summary, Checkout / Payment, Identification, DeliveryMethodRadioGroup, Account / DataBlock, CollapsibleSection) haben ein max-w an `[twuc]-128` (512). Figma nimmt an Texten keine Bindung an eine Width-Variable an. Der Wert ist in allen Modi gleich, deshalb ist das unkritisch.
- **Width-Variablen ohne Code-Syntax:** Keine der 36 Variablen hat eine Code-Syntax für Web. Der Dev Mode zeigt dadurch Namen, die es in `app.tcss` nicht gibt.
- **MegaCard / MegaCards** auf `Breakpoint = base · md · lg` umstellen.
