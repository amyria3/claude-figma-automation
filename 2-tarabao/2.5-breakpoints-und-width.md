# 2.5 Breakpoints und Width-Variablen

Stand: 23.09.2026 · Figma-Datei „B2C und CI“, Seite COMPONENTS & SCREENS

Dieses Kapitel erklärt, wie die Breiten im Figma-File mit den Breakpoints zusammenhängen und wo du als Entwickler:in die Werte in Figma abliest.

![Übersicht: Fensterbreite, Page-Variante, Modus und Grenzen](<img width="1400" height="448" alt="image" src="https://github.com/user-attachments/assets/04964fee-0567-4992-94c7-e4b03b258aac" />)

## Das Prinzip in drei Sätzen

1. **Die Seite bestimmt den Breakpoint.** `Templates / Page` hat drei Varianten (`base`, `md`, `lg`). Jede Variante trägt die Grenzen ihres Bereichs und pinnt den passenden Modus der Collection `Lyt scl / Width`.
2. **Die Werte hängen am Modus.** Alle Breiten in `Lyt scl / Width` haben je Modus einen eigenen Wert. Eine Komponente auf einer md-Seite rechnet also automatisch mit den md-Werten.
3. **Komponenten schalten mit.** Footer, NavBar, Nav, PromoBar und Nutmixer haben eine Property `Breakpoint`. Sie ist an die Text-Variable `breakpoint` gebunden und wählt deshalb die Variante, die zur Seite passt.

## Die drei Collections

| Collection | Inhalt | Modi | Im Code |
| --- | --- | --- | --- |
| `Lyt scl / Breakpoints` | `base` 360 · `md` 768 · `lg` 1024 | einer („Fensterbreite“) | `--breakpoint-md: 48rem`, `--breakpoint-lg: 64rem` (Tailwind-Standard). `base` hat keine Media-Query. |
| `Lyt scl / Width` | alle Element-Breiten (min-w, max-w) plus die Seitengrenzen | `base` · `md` · `lg` | Werte, die sich je Modus unterscheiden, werden zu responsiven Klassen (siehe unten). |
| `Lyt scl / Tailwind-utility-units` | Primitive in rem, z. B. `[twuc]-96 (24rem)` | einer | Tailwind-Utility, z. B. `min-w-96` |

Breakpoints stehen in einer eigenen Collection, weil sie Schwellen der Fensterbreite sind und keine Maße eines Elements.

![Collection Lyt scl / Breakpoints](img/breakpoints/03-collection-breakpoints.png)

## Die Seitengrenzen in `Lyt scl / Width`

Ganz oben in `Lyt scl / Width` stehen fünf Variablen, die nur für den Seitenrahmen gelten:

| Variable | base | md | lg | Zweck |
| --- | --- | --- | --- | --- |
| `breakpoint` | „base“ | „md“ | „lg“ | schaltet die Varianten eingebetteter Komponenten |
| `min-w-screen` | → Breakpoints/base (360) | → Breakpoints/md (768) | → Breakpoints/lg (1024) | untere Grenze der Page-Variante |
| `max-w-screen` | → Breakpoints/md (768) | → Breakpoints/lg (1024) | 3840 | obere Grenze der Page-Variante. 3840 ist ein Platzhalter, weil lg kein Maximum hat. |
| `min-w-content` | 320 | 728 | 984 | kleinste Inhaltsbreite (Fenster − 2 × 20 Rand). Kein min-w eines Elements darf darüber liegen. |
| `max-w-content` | 1064 | 1064 | 1064 | größte Inhaltsbreite; ab 1104 px Fenster steht der Inhalt und wird zentriert |

![Collection Lyt scl / Width mit den drei Modi](img/breakpoints/05-collection-width-modi.png)

① Die Modi heißen nach dem Bereich, in dem sie gelten: „md · min=md, max=lg−1“ bedeutet 768 bis 1023 px.
② Die Seitengrenzen und Inhaltsbreiten je Modus.

`min-w-screen`, `max-w-screen` und `breakpoint` gibt es nur in Figma. Im Code sind Breakpoints Konstanten, weil eine Media-Query keine CSS-Variable lesen kann (`@media (min-width: var(--x))` ist ungültig).

## So liest du die Werte in Figma ab

### 1. Welcher Breakpoint gilt für einen Frame?

Wähle im **Dev Mode** eine Seite oder eine Variante von `Templates / Page` aus und sieh dir im Inspect-Panel **Layout** und **Modes** an:

![Dev Mode: Layout und Modes einer Page-Variante](img/breakpoints/02-devmode-page-layout-und-modus.png)

① `min-width: var(--min-w-screen, 768px)` und `max-width: var(--max-w-screen, 1024px)` zeigen den Bereich dieser Seite: 768 bis 1023 px, also Tailwind `md`.
② Unter **Modes** steht bei `Lyt scl / Width` der aktive Modus. Alle Breiten dieser Seite und ihrer Komponenten kommen aus diesem Modus.

Übersetzung in den Code: Die Figma-Grenze `max-width: 1024px` heißt im CSS „bis `lg` ausschließlich“. Tailwind schreibt das als `md:` bzw. `max-lg:`.

### 2. Welcher CSS-Name gehört zu einem Breakpoint?

Öffne links **Variables** → `Lyt scl / Breakpoints` und klicke eine Variable an:

![Variable md mit Code-Syntax](img/breakpoints/04-breakpoint-variable-code-syntax.png)

① Unter **Code syntax → Web** steht der Name im Code, hier `var(--breakpoint-md)`. Die Beschreibung darüber sagt, was sich ab dieser Breite ändert.

### 3. Warum sieht eine Komponente je Seite anders aus?

Wähle eine eingebettete Komponente aus, z. B. den Footer in einer Page-Variante:

![Dev Mode: Footer mit gebundener Breakpoint-Property](img/breakpoints/06-devmode-footer-breakpoint-property.png)

① Die Property `Breakpoint` zeigt kein festes „md“, sondern die Variable `breakpoint`. Der Footer übernimmt damit die Variante des Modus, in dem er liegt. Im Code braucht er dafür keine Prop: Die Varianten zeigen, wie die Komponente in diesem Breitenbereich aussieht, umgesetzt wird das mit responsiven Klassen.

## Von Figma zu Tailwind

| Figma | Code |
| --- | --- |
| Page-Variante `base` / `md` / `lg` | Klassen ohne Präfix / `md:` / `lg:` |
| Width-Variable mit gleichem Wert in allen Modi, z. B. `Block Element/max-w` = 512 | eine Klasse: `max-w-128` |
| Width-Variable mit Werten je Modus, z. B. `Block Element/min-w` = 320 · 320 · 384 | `min-w-80 lg:min-w-96` |
| `max-w-content` im Kind `wrapper-max-w` einer Section | `mx-auto max-w-[66.5rem] px-5` im inneren Container, Hintergrund auf der Section selbst |
| Komponente mit `Breakpoint`-Varianten | eine Komponente mit responsiven Klassen, keine Breakpoint-Prop |

## Regeln für Design und Pflege

- **Grenzen nur am Seitenrahmen.** Nur `Templates / Page` bindet `min-w-screen` / `max-w-screen` und pinnt den Modus. `Pages / …` wie ProductPage tragen keine eigenen Grenzen, sie wählen die passende Page-Variante.
- **Komponenten pinnen keinen Modus.** Eine Instanz übernimmt den Pin ihres Masters. Hätte die Variante `Footer › lg` einen lg-Pin, bliebe jede Footer-Instanz auf lg stehen, egal auf welcher Seite.
- **Kein min-w über `min-w-content`.** Sonst läuft das Element auf dem kleinsten Bildschirm über.
- **Hintergrund volle Breite, Inhalt begrenzt.** Sections laufen bis zum Fensterrand. Der Inhalt begrenzt sich im Kind `wrapper-max-w` (max-w-content + 20 px Rand).
- **Figma kann nicht rechnen.** Ändert sich `Breakpoints/base`, muss `min-w-content` (base) von Hand mitgeändert werden: base − 40.
