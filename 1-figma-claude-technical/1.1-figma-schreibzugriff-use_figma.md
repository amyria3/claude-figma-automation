# Figma write access (`use_figma`) — setup & usage

**Status:** 2026-08-03 (translated to English per repo language rule; primary path verified 2026-07-15)

## What this is

Figma's **remote MCP server** (`https://mcp.figma.com/mcp`) supports **write access to the canvas** (free beta at the time of writing) — unlike the local Dev Mode server (`http://127.0.0.1:3845/mcp`, read-only: `get_metadata`, `get_design_context`, `get_screenshot`).

There are **two paths** to this remote server. Path 1 is primary.

---

## Path 1 (PRIMARY): connect the Figma connector directly in Cowork/claude.ai

**No terminal, no Claude Code, no Desktop Commander needed.** The Figma remote MCP is available as a connector in Claude's MCP registry and can be connected directly in the session.

> ⚠️ **Note for Claude:** this path was frequently overlooked in earlier sessions in favour of the cumbersome Claude-Code detour (path 2). **Always check first whether the Figma connector is available/connected** (`search_mcp_registry` with ["figma"], or scan the tool list for `use_figma`) before considering path 2.

### Setup

1. Claude searches the MCP registry for "Figma" (`mcp__mcp-registry__search_mcp_registry`) and suggests the connector (`suggest_connectors`).
2. The user clicks **Connect** → confirms the browser OAuth login with Figma.
3. The remote MCP tools are then available directly in the session.

### Available tools after connecting (selection)

| Tool | Purpose |
|---|---|
| `use_figma` | **Write access**: run JavaScript via the Figma Plugin API (create/modify nodes, variables, components, …) |
| `get_metadata`, `get_design_context`, `get_screenshot`, `get_variable_defs` | Reading |
| `get_figma_skill` | Load the mandatory `figma-use` skill (see below) |
| `create_new_file`, `generate_diagram`, `search_design_system`, `whoami` | Other functions |

**Caution:** the connector's registry description lists only read tools — `use_figma` appears in the tool list only **after** connecting. Don't be misled.

### Mandatory preparation before every use_figma call

Load the skill via `get_figma_skill` with URI `skill://figma/figma-use/SKILL.md`, then pass `skillNames: "resource:figma-use"` on the `use_figma` call. Key rules from the skill:

- Code is plain JavaScript with top-level `await` and `return` (no IIFE, no `figma.closePlugin()`)
- Before text mutations: `await figma.loadFontAsync(...)` (when it's actually needed: `1.3-figma-api-reference.md` §1️⃣)
- Page switches only via `await figma.setCurrentPageAsync(page)`
- Return all created/changed node IDs via `return`
- Max. ~10 logical operations per call, work incrementally
- Position new top-level nodes away from (0,0)

### Test check after every fresh setup

`use_figma` with the `fileKey` from the file URL; the code creates a text node `[TEST_SCHREIBZUGRIFF_OK]`.

### Differences vs. path 2

- The Figma file does **not** need to be open in the desktop app (the remote server runs server-side).
- The file URL / file key is still required (`fileKey` parameter).
- Auth runs via browser OAuth, no terminal needed.

## Path 2 (FALLBACK): drive Claude Code via a terminal tool

Only needed if the connector is unavailable. Official Figma plugin for Claude Code (`figma@claude-plugins-official`), connected to the same remote MCP server. Runs only in **Claude Code** (terminal); Claude drives Claude Code via a terminal tool (e.g. Desktop Commander).

### Installation (one-time)

```bash
# 1. Add the official plugin marketplace
claude plugin marketplace add anthropics/claude-plugins-official

# 2. Install the Figma plugin
claude plugin install figma@claude-plugins-official

# 3. Check the connection
claude mcp list
# → should show: plugin:figma:figma  https://mcp.figma.com/mcp (HTTP) - ! Needs authentication
```

**Authentication** (needs a real, interactive terminal window — not a background process):
```bash
claude
```
Then in the session, e.g.: "Authenticate with Figma" → confirm the browser login.

Afterwards `claude mcp list` shows:
```
plugin:figma:figma: https://mcp.figma.com/mcp (HTTP) - ✓ Connected
```

### Usage (path 2)

- **The Figma file must be open in the desktop app.**
- Claude needs the **file URL** (Share → Copy link, format `https://www.figma.com/design/XXXX/...`) — no file key, no write access.
- Before every `use_figma` call, Claude Code loads the `figma:figma-use` skill automatically.

**Typical flow (example prompt):**
> "Use use_figma to create a text node with content '...' on the active page of [file URL]."

**Other relevant skills in the same plugin:**

| Skill | Purpose |
|---|---|
| `figma-create-new-file` | Create a new Figma/FigJam/Slides file |
| `figma-generate-design` | Build whole pages/screens from code/description |
| `figma-generate-library` | Build a design system (variables, components) |
| `figma-generate-diagram` | Flowcharts, ERDs etc. in FigJam |
| `figma-code-connect` | Link Figma components to code |

### Known pitfalls (path 2)

- `claude` without a real terminal (e.g. as a background process) starts **no** interactive session → the auth flow fails. Authenticate once in a real terminal; the token stays valid afterwards.
- The local read server (127.0.0.1:3845) and the remote write server are **two separate connections** — both can exist in parallel.
- Without the file URL, `use_figma` cannot determine the file key, even if the file is open in Figma Desktop.
