## 0. Rules that override instinct

1. **Always read Figma live.** Never derive values from the docs, the CSS, or memory.
2. **The CSS mirrors Figma 1:1.** A wrong value gets corrected **in Figma**, never patched in the CSS. Reproduce oddities faithfully and report them.
3. **`app.tcss` contains only the transmission.** Structural comments plus px→rem and alias provenance. No status notes, no design rationale. **No change log is kept** — the CSS mirrors Figma, so the current state is the documentation.
4. **Verify by building, not by reading.** A wrong `@theme` namespace throws no error — the tokens are simply silent.
5. Not mapped: every collection whose name starts with `__` (content data).

## 1. Read the current state

```js
const cs = await figma.variables.getLocalVariableCollectionsAsync();
return cs.map(c => ({ name: c.name, count: c.variableIds.length, modes: c.modes.map(m => m.name) }));
```

Then dump the collections with **per-mode alias name and resolved hex** — the alias name shows which primitive was intended. Resolve aliases recursively; cross-collection aliases resolve against the target collection default mode.

## 2. Where each collection goes

| Figma | CSS section | mechanism |
|---|---|---|
| `Clrs / Primitives` | §1 `:root` | raw hex, never referenced by components |
| `Clrs / Color Modes` (4 modes) | §2a | `@theme inline` + 4 × `[data-theme]` |
| single-mode colour collections | §2b | fixed in `:root`, never inside `[data-theme]` |
| multi-mode but **not** brand×surface | §2c | own parallel axis, e.g. `[data-lively-theme]` |
| `Lyt scl / Heights` | §2d + §5 | `:root` vars → `@utility` |
| `Typografy`, Text Styles, spacings, widths | §4 | plain `@theme` |

The 4 global modes: `cole-tint-surface-warm` (default), `cole-tint-surface-snow`, `purple-tint-surface-warm`, `purple-tint-surface-snow` — brand (cole/purple) × surface (warm/snow).

### Namespace traps (Tailwind v4)

| purpose | wrong | right |
|---|---|---|
| font size | `--font-size-*` | `--text-*` |
| width | `--width-*` | `--container-*` |
| height | `--height-*` | no namespace exists → `@utility` |

`--font-*` is font **family** only. `--spacing-*` feeds `p-*`, `m-*`, `gap-*`, `space-*` from one scale. Colours **must** be `@theme inline` so utilities emit `var(--…)` and stay switchable at runtime; static scales go in plain `@theme`.

## 3. Naming conventions (agreed 28.07.2026)

**State vocabulary — closed set:** `-default`, `-hover`, `-focused`, `-selected`, `-selected-hover`, `-inactive`. No `on-` prefix. One token covering two states uses `&` in fixed order: `-hover-&-click`.

- `-inactive`, **not** `-disabled` — the button stays clickable and returns an error, so it is not technically disabled.
- `-focused`, **not** `-active`, for fields in use — that is `:focus`; CSS `:active` means „being pressed".

**Property vocabulary:** `bg`, `label`, `stroke`; combined always `label-&-stroke` (never `stroke-&-label`). `&` means one variable feeds two CSS properties.

**Mode names encode exactly one axis.** LG Primary modes are hue-only (`purple`, `sky-blue`, `yellow`, `orange`), not hue + surface.

**Spelling:** variable names kebab-case, no spaces; group names may keep spaces. **No number in a name that can contradict the value** — on conflict the px value wins and the name is corrected.

**Derivation Figma → CSS:** `Button-X/button-x-<role>-<state>` → `--btn-x-<role>-<state>`: `button` → `btn`, `-default` dropped, category prefix kept. Size-scoped sets keep their prefix (`--lg-primary-*`). Exactly one group level per collection.

## 4. Recipes

**A. Token added to an existing 4-mode collection** — add it to **all four** blocks *and* register it in `@theme inline`.

**B. Single value changed in one mode** — edit that line, then re-run the full verification.

**C. New collection appears** — two questions decide:
1. *Do values differ per mode?* No → single-mode in `:root`; never re-declare under `[data-theme]`. That is the opt-out.
2. *If yes, are the modes brand×surface?* Yes → global 4 modes. No → **parallel theme axis**: own `data-*` attribute, own token prefix.

A parallel axis is the same attribute-selector trick as `data-theme` with a disjoint namespace, so both compose on one element. Keep the `data-` prefix; avoid `data-theme` (claimed by next-themes, daisyUI). Two groups sharing one axis need value prefixes (`mc-`, `lg-`).

**D. Renaming a token — a name lives in THREE places:** the declaration in all four mode blocks, the `@theme inline` registration (`--color-x`), and the right-hand side of that registration (`var(--x)`). Change only some and the variable is defined in a subset of modes; the utilities then silently produce nothing in the rest, with no build error. After any rename assert: the old name appears **zero** times, and registration count equals reference count.

**E. Completeness rule — non-negotiable.** Every `[data-theme]` block declares the **full** token set, and the default gets its own selector:

```css
:root, [data-theme="cole-tint-surface-warm"] { /* all tokens */ }
```

Custom properties inherit, so a diff-only block works solely while its parent is the default. Without the explicit default selector no subtree can switch back. Applies to every parallel axis.

## 5. Verify (never skip)

```bash
npm install tailwindcss @tailwindcss/cli
npx @tailwindcss/cli -i app.tcss -o out.css --content t.html
```

1. **Build clean.**
2. **Utilities exist** — grep the output for each expected class.
3. **Completeness first, values second.** Count declarations per block *and* the union of token names across blocks. All counts equal **and** equal the union size. A union larger than the per-block count means blocks are missing tokens — the failure a value-diff hides, because absent tokens get skipped rather than flagged.
4. **Values** — resolve every token through its full `var()` chain to a final hex and diff against the live Figma dump. Target: zero mismatches, zero unresolved.

## 6. Figma gotchas

- **Stale variable names.** `getVariableByIdAsync` can return a variable old name after a rename. Verify names against the full collection listing, never the getter on an alias target. Values are reliable; names are not.
- **Names can lie about values.** Check resolved px: a variable called `(48rem)` held 674px. Rule: 1 twuc = 4px, rem = px ÷ 16.
- **Raw hex in a semantic collection** breaks the two-layer model — add primitives and alias to them.
- **Bindings may be instance-level.** Scan for master bindings *and* instance overrides; the same override can be reported at several nesting depths, so rebinding 30 nodes can clear 51 reported hits. Re-scan afterwards. `setBoundVariableForPaint` returns a **new** paint — reassign the array.
- **Renames are ID-based** — bindings survive, so renaming is safe.
- **`use_figma` is atomic per script.** In batch mutations wrap each node in its own try/catch.
- **New variables:** set `scopes` explicitly; this library uses `[ALL_SCOPES]`.
- **Page context resets** between calls; call `setCurrentPageAsync` at most once per script.

## 7. Committing via the GitHub web editor

- **Never read file content from `.cm-line`** — CodeMirror virtualises, so only ~20 visible lines exist in the DOM. Reading them and writing back **truncates the file**. Always fetch current content from the GitHub API, patch the string, then `focus()` → `execCommand(selectAll)` → `execCommand(insertText, …)` on `.cm-content`. Recoverable while uncommitted: re-fetch and redo.
- Renaming a file: set the filename field via the native value setter + `input` event, then commit.
- **The GitHub API caches.** After committing, re-fetch with a cache-buster and `{cache:no-store}` before concluding a commit failed. `raw.githubusercontent.com` lags minutes and can serve a version missing whole sections.
- Copilot may overwrite a custom commit message — check the result.
- In `javascript_tool`, if the script uses `return` anywhere the trailing expression is **not** auto-returned — end with an explicit `return`, or avoid `return` entirely.
- Sanitisation can redact output that looks key-like or contains query strings; return small structured flags rather than raw markdown.

## 9. Mentor mode — design system to frontend (pairing)

Trigger: Maria wants to stand up the frontend and check that the design system flows into code without gaps. Here you are a **mentor, not an autopilot** — pair with her, explain the *why* of each step, keep steps small, confirm before moving on, and let her drive. Teach the moves so she can repeat them; the frontend setup itself (framework, repo, build) is decided together, not assumed.

1. **Frontend base.** Wire Tailwind v4 with `app.tcss` as the entry (`@import "tailwindcss"`). Prove that one token utility renders (`bg-surface-color`, `text-content-text`) before building anything else.
2. **Figma access (only if missing).** Set up the Figma Dev Mode MCP / API together and verify with a read (`whoami`, then one `get_design_context` on a node). Reads are enough here — no write access needed.
3. **Generate via Figma own prompts.** Use the guidance Figma ships — `get_design_context`, `/figma-design-to-code`, Code Connect — to generate one component or screen. The test is whether *their* output lands on *our* tokens, so prefer their prompts over hand-writing the markup.
4. **Seam check (the actual goal).** Verify the generated code consumes the system cleanly: every colour comes from a `--color-*`-backed utility (`bg-*` / `text-*` / `border-*`), never a raw hex; theming happens via the `data-theme` / `data-special-theme` / `data-lively-theme` attributes, not duplicated colour sets; spacing via `--spacing-*`, type via `--text-*` / `--leading-*` / `--tracking-*`, widths via `--container-*`. Any hardcoded value is a gap — fix it at the source (bind the variable in Figma, then re-sync `app.tcss` per sections 1–5), not in the component.
5. **Loop** on a representative screen until it renders from tokens only. That is the pass condition: the design system is code-ready.

Section 0 stays in force throughout: `app.tcss` mirrors Figma, values are corrected in Figma, and you verify by building (section 5), not by eyeballing.
