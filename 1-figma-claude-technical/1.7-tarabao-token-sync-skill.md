## 0. Rules that override instinct

1. **Always read Figma live.** Never derive values from the docs, the CSS, or memory — the library changes between sessions.
2. **The CSS mirrors Figma 1:1.** A wrong value gets corrected **in Figma**, never patched in the CSS. Reproduce oddities faithfully and report them.
3. **`app.tcss` contains only the transmission.** Structural comments (which collection / component / theme belongs to which token block) plus px→rem and alias provenance. **No** change logs, no status notes, no design rationale. Design rules live in the design system. **No change log is kept** — the CSS mirrors Figma, so the current state is the documentation.
4. **Verify by building and by the check script, not by reading.** A wrong `@theme` namespace throws no error — the tokens are simply silent. `token_check.py` must end with 0 errors (§5).
5. Not mapped: every collection whose name starts with `__` (content data) and `Lyt scl / Tailwind-utility-units` (the built-in Tailwind scale behind the aliases).
6. **Code syntax is the naming contract.** Every Figma variable that reaches code carries **Code syntax → Web** `var(--name)`, and `--name` exists in `app.tcss`. Variables that exist only for the Figma simulation have no code syntax and the words "Nur Figma" in their description.

## 2. Where each collection goes

| Figma | CSS section | mechanism |
|---|---|---|
| `Clrs / Primitives` | §1 `:root` | raw hex, never referenced by components |
| `Clrs / Color Modes` (4 modes) | §2a | `@theme inline` + 4 × `[data-theme]` |
| single-mode colour collections | §2b | fixed in `:root`, never inside `[data-theme]` |
| multi-mode but **not** brand×surface | §2c / §2e | own parallel axis: `[data-lively-theme]` (Mega Cards), `[data-special-theme]` (Special) |
| `Lyt scl / Heights` | §2d + §5 | `:root` vars → `@utility` |
| `Lyt scl / Breakpoints` | §4 | `--breakpoint-*: initial;` then `--breakpoint-md`, `--breakpoint-lg` only. `base`, `calc(…)`, `x-lg` are "Nur Figma" |
| `Lyt scl / Width` | §4 | `--container-*` in `@theme static` (base value) + `:root { @variant md/lg }` for values per mode |
| `Lyt scl / Width` › `min-w-content`, `max-w-content` | §4 + §5 | `--content-min` / `--content-max` in `:root` (per mode) + `@utility min-w-content` / `max-w-content`. Widths aliasing `max-w-content` → `var(--content-max)` |
| `Typografy`, spacings | §4 | plain `@theme static` |
| Text Styles | §4 + §6 | families / leading / tracking in §4, one `@utility type-*` per style in §6 |

The 4 global modes: `cole-tint-surface-warm` (default), `cole-tint-surface-snow`, `purple-tint-surface-warm`, `purple-tint-surface-snow` — brand (cole/purple) × surface (warm/snow).

### Namespace traps (Tailwind v4)

| purpose | wrong | right |
|---|---|---|
| font size | `--font-size-*` | `--text-*` |
| width | `--width-*` | `--container-*` (gives `w-`/`min-w-`/`max-w-`/`basis-`) |
| height | `--height-*` | no namespace exists → `@utility` |

`--font-*` is font **family** only. `--spacing-*` feeds `p-*`, `m-*`, `gap-*`, `space-*` from one scale — Box Spacing and Gaps collapse into it.

A `--container-x` token creates `min-w-x` **and** `max-w-x`. For `content` this produced `min-w-content` with the maximum value, hence the explicit `@utility` pair.

Tailwind's default scales stay active unless reset: `--breakpoint-*: initial` removes `sm`, `xl`, `2xl`.

Colours **must** be `@theme inline` so utilities emit `var(--…)` and stay switchable at runtime; without `inline` the values freeze at build time. Static scales go in `@theme static` so they are also emitted as CSS variables.

## 3. Naming conventions (agreed 28.07.2026)

**State vocabulary — closed set:** `-default`, `-hover`, `-focused`, `-selected`, `-selected-hover`, `-inactive`. No `on-` prefix. One token covering two states uses `&` in fixed order: `-hover-&-click`.

- `-inactive`, **not** `-disabled` — the button stays clickable and returns an error, so it isn't technically disabled.
- `-focused`, **not** `-active`, for fields in use — that is `:focus`; CSS `:active` means "being pressed".

**Property vocabulary:** `bg`, `label`, `stroke`; combined always `label-&-stroke` (never `stroke-&-label`). `&` means one variable feeds two CSS properties.

**Mode names encode exactly one axis.** LG Primary modes are hue-only (`purple`, `sky-blue`, `yellow`, `orange`), not hue+surface.

**Spelling:** variable names kebab-case, no spaces. Group names may keep spaces. **No number in a name that can contradict the value** — on conflict the px value wins and the name is corrected. The same holds for code syntax: it must not point to a token with a different value.

**Derivation Figma → CSS:** `Button-X/button-x-<role>-<state>` → `--btn-x-<role>-<state>`: `button` → `btn`, `-default` dropped, category prefix kept (it prevents collisions, not the role). Size-scoped sets keep their prefix (`--lg-primary-*`). Exactly one group level per collection.

**Text style → class:** prefix `type-`, `/` and spaces become `-`, camel case is split, `&` and `<>` are dropped, lower case. `ShoppingCart & Checkout/MainHeadline` → `type-shopping-cart-checkout-main-headline`. `slug()` in `token_check.py` is the reference.

## 4. Recipes

**A. Token added to an existing 4-mode collection** — add it to **all four** blocks *and* register it in `@theme inline`.

**B. Single value changed in one mode** — edit that line, then re-run the full verification.

**C. New collection appears** — two questions decide:
1. *Do values differ per mode?* No → single-mode in `:root`; never re-declare under `[data-theme]`. That is the opt-out.
2. *If yes, are the modes brand×surface?* Yes → global 4 modes. No → **parallel theme axis**: own `data-*` attribute, own token prefix. Add the collection to `AXES` in `figma-dump.js`.

A parallel axis is the same attribute-selector trick as `data-theme` with a disjoint namespace, so both compose on one element. Keep the `data-` prefix; avoid `data-theme` (claimed by next-themes, daisyUI). Two groups sharing one axis need value prefixes (`mc-`, `lg-`).

**D. Renaming a token — a name lives in THREE places:** the declaration in all four mode blocks, the `@theme inline` registration (`--color-x`), and the right-hand side of that registration (`var(--x)`). Change only some and the variable is defined in a subset of modes; the utilities then silently produce nothing in the rest, with no build error. After any rename assert: the old name appears **zero** times, and registration count equals reference count. Change the code syntax in Figma in the same step.

**E. Completeness rule — non-negotiable.** Every `[data-theme]` block declares the **full** token set, and the default gets its own selector:

```css
:root, [data-theme="cole-tint-surface-warm"] { /* all tokens */ }
```

Custom properties inherit, so a diff-only block works solely while its parent is the default. Without the explicit default selector no subtree can switch back. Applies to every parallel axis.

**F. Text style added or changed** — regenerate §6: `python3 token_check.py dump.txt ../app.tcss --emit-type` prints all `@utility type-*` blocks; replace the block list below the §6 header with it. A style whose font size is not bound to a `Typografy` variable, or whose line height / letter spacing has no token, is reported as an error: fix it in Figma.

**G. Width variable per mode** — base value in `@theme static`, md/lg values in the `:root { @variant md { … } @variant lg { … } }` block. If the Figma variable aliases `max-w-content`, write `var(--content-max)` and it switches automatically.

## 5. Verify (never skip)

```bash
npm install tailwindcss @tailwindcss/cli
npx @tailwindcss/cli -i app.tcss -o out.css --content t.html   # t.html lists every expected class
python3 token-check/token_check.py dump.txt app.tcss             # dump.txt from figma-dump.js (§1)
```

1. **Build clean**, and grep the output for each expected class.
2. **`token_check.py` ends with `Fehler: 0`.** It checks:
   - every code syntax `var(--x)` from Figma exists in `app.tcss` (`FEHLT`),
   - every value in every mode, resolved through the full `var()` chain to hex or px (`WERT`),
   - one CSS name gets only one value from Figma (`KONFLIKT`),
   - every block of a theme axis declares the same token set (`LÜCKE`) — completeness first, because a value diff silently skips absent tokens,
   - every non-primitive colour has a `--color-*` registration pointing to a declared variable (`REG`),
   - every text style has its `@utility type-*` with identical declarations (`TEXT`),
   - custom properties under a selector that is neither `:root` nor `[data-*="…"]` (`SELEKTOR`) — almost always a comment that ended early.
3. **Read the hints.** Variables without code syntax that are not marked "Nur Figma", CSS variables without a Figma counterpart, leading/tracking tokens no text style uses. Report them; they are not errors.
4. **Negative test after changing the script:** alter one value in a copy of `app.tcss` and confirm the script reports it.

## 6. Figma gotchas

- **Stale variable names.** `getVariableByIdAsync` can return a variable's *old* name after a rename. Verify names against the full collection listing, never the getter on an alias target. Values are reliable; names are not.
- **Names can lie about values.** Check resolved px: a variable called `(48rem)` held 674px. Rule: 1 twuc = 4px, rem = px ÷ 16.
- **Raw hex in a semantic collection** breaks the two-layer model — add primitives and alias to them.
- **Bindings may be instance-level.** Scan for master bindings *and* instance overrides; the same override can be reported at several nesting depths, so rebinding 30 nodes can clear 51 reported hits. Re-scan afterwards. `setBoundVariableForPaint` returns a **new** paint — reassign the array.
- **Renames are ID-based** — bindings survive, so renaming is safe. **Deleting is final:** a recreated variable gets a new ID. Before deleting, list every alias and node binding across all pages.
- **`use_figma` is atomic per script.** In batch mutations wrap each node in its own try/catch.
- **`use_figma` returns about 20 kB.** Larger outputs are cut off silently — split reads (`PART` in `figma-dump.js`).
- **New variables:** set `scopes` explicitly; this library uses `['ALL_SCOPES']` for colours and `['WIDTH_HEIGHT']` for breakpoints.
- **Page context resets** between calls; call `setCurrentPageAsync` at most once per script and fan multi-page work out in parallel.
- **Ground truth is `resolveForConsumer`.** Getter values (`valuesByMode`) can lag a live edit within a session; before correcting the CSS, confirm the hex with both the getter and `resolveForConsumer` — if they disagree, the value changed under you, re-read.

## 6a. CSS gotchas

- **Never write `*/` inside a comment** — not even in `Buttons/*/Inline` or `--error-*/--success-*`. It ends the comment; the rest becomes the selector of the next rule, and browsers drop that whole block. Tailwind builds without an error. Write `Buttons/…/Inline`. `token_check.py` reports it as `SELEKTOR`.
- **Nested `& + &` inside `@utility`** is flattened by `--optimize` builds; without it the output keeps native CSS nesting.

## 7. Committing to GitHub

- **Git push from the cloud session fails** (proxy 403). Working route for whole files: write the files into the connected folder `Claude outputs/…` (`device_commit_files`), stage them (`device_stage_files`, they land in `/mnt/user-data/uploads/…`), then upload them with claude-in-chrome `file_upload` on `github.com/amyria3/claude-figma-automation/upload/main/<folder>`, enter the commit message and commit. `file_upload` does not read from `/mnt/user-data/outputs`.
- Before replacing a file, compare it with the current `main` (fresh clone or Contents API) so a newer commit is not overwritten.
- **Web editor:** never read file content from `.cm-line` — CodeMirror virtualises, so only ~20 visible lines exist in the DOM. Reading them and writing back **truncates the file**. Always fetch current content from the GitHub API (or the open editor's CodeMirror document), patch the string, then write it back with `view.dispatch` / `execCommand('insertText', …)`. Recoverable while uncommitted: re-fetch and redo.
- CM6 full-replace: `view.dispatch({changes:{from:0,to:view.state.doc.length,insert:text}})` is reliable; `execCommand('selectAll')+delete` sometimes does not clear the editor.
- Renaming a file: set the filename field via the native value setter + `input` event, then commit — GitHub records it as a rename.
- **The GitHub API caches.** After committing, re-fetch with a cache-buster and `{cache:'no-store'}` before concluding a commit failed; also check the commits endpoint. `raw.githubusercontent.com` lags minutes and can serve a version missing whole sections.
- In `javascript_tool`, if a returned string contains hex, `=`, `?`, `&`, or long alphanumeric tokens it is redacted as "Cookie/query string data" — return small counts/booleans, not raw CSS, when verifying via the browser.

## 9. Mentor mode — design system to frontend (pairing)

Trigger: Maria wants to stand up the frontend and check that the design system flows into code without gaps. Here you are a **mentor, not an autopilot** — pair with her, explain the *why* of each step, keep steps small, confirm before moving on, and let her drive. Teach the moves so she can repeat them; the frontend setup itself (framework, repo, build) is decided together, not assumed.

1. **Frontend base.** Wire Tailwind v4 with `app.tcss` as the entry (`@import "tailwindcss"`). Prove that one token utility renders (`bg-surface-color`, `text-content-text`, `type-h1`) before building anything else.
2. **Figma access (only if missing).** Set up the Figma Dev Mode MCP / API together and verify with a read (`whoami`, then one `get_design_context` on a node). Reads are enough here — no write access needed.
3. **Generate via Figma own prompts.** Use the guidance Figma ships — `get_design_context`, `/figma-design-to-code`, Code Connect — to generate one component or screen. The test is whether *their* output lands on *our* tokens, so prefer their prompts over hand-writing the markup.
4. **Seam check (the actual goal).** Verify the generated code consumes the system cleanly: every colour comes from a `--color-*`-backed utility (`bg-*` / `text-*` / `border-*`), never a raw hex; theming happens via the `data-theme` / `data-special-theme` / `data-lively-theme` attributes, not duplicated colour sets; spacing via `--spacing-*`, type via `type-*` classes (or `--text-*` / `--leading-*` / `--tracking-*`), widths via `--container-*` and `min-w-content` / `max-w-content`, breakpoints only `md:` / `lg:`. Any hardcoded value is a gap — fix it at the source (bind the variable in Figma, then re-sync `app.tcss` per sections 1–5), not in the component.
5. **Loop** on a representative screen until it renders from tokens only. That is the pass condition: the design system is code-ready.

Section 0 stays in force throughout: `app.tcss` mirrors Figma, values are corrected in Figma, and you verify by building and by `token_check.py` (section 5), not by eyeballing.
