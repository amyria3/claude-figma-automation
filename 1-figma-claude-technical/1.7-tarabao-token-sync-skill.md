## 0. Rules that override instinct

1. **Always read Figma live.** Never derive values from the docs, the CSS, or memory — the library changes between sessions.
2. **The CSS mirrors Figma 1:1.** A wrong value gets corrected **in Figma**, never patched in the CSS. Reproduce oddities faithfully and report them.
3. **`app.tcss` contains only the transmission.** Structural comments (which collection / component / theme belongs to which token block) plus px→rem and alias provenance. **No** change logs, no status notes, no design rationale. Design rules live in the design system; history lives in `2.4`.
4. **Verify by building, not by reading.** A wrong `@theme` namespace throws no error — the tokens are simply silent.
5. Not mapped: every collection whose name starts with `__` (content data).

## 1. Where each collection goes

| Figma | CSS section | mechanism |
|---|---|---|
| `Clrs / Primitives` | §1 `:root` | raw hex, never referenced by components |
| `Clrs / Color Modes` (4 modes) | §2a | `@theme inline` + 4 × `[data-theme]` |
| single-mode colour collections | §2b | fixed in `:root`, never inside `[data-theme]` |
| multi-mode but **not** brand×surface | §2c | own parallel axis, e.g. `[data-lively-theme]` |
| `Lyt scl / Heights` | §2d + §5 | `:root` vars → `@utility` |
| `Typografy`, Text Styles, spacings, widths | §4 | plain `@theme` |

The 4 global modes: `cole-tint-surface-warm` (default), `cole-tint-surface-snow`, `purple-tint-surface-warm`, `purple-tint-surface-snow` — brand (cole/purple) × surface (warm/snow).

### Namespace traps (Tailwind v4)

| purpose | wrong | right |
|---|---|---|
| font size | `--font-size-*` | `--text-*` |
| width | `--width-*` | `--container-*` (gives `w-`/`min-w-`/`max-w-`/`basis-`) |
| height | `--height-*` | no namespace exists → `@utility` |

`--font-*` is font **family** only. `--spacing-*` feeds `p-*`, `m-*`, `gap-*`, `space-*` from one scale — Box Spacing and Gaps collapse into it.

Colours **must** be `@theme inline` so utilities emit `var(--…)` and stay switchable at runtime; without `inline` the values freeze at build time. Static scales go in plain `@theme` so they are also emitted as CSS variables.

### Naming: derivation rule

`Button-X/button-x-<role>-default` → `--btn-x-<role>`: `button` → `btn`, drop `-default`, keep the variant. So `option-selection-button-bg-default` → `--btn-option-selection-bg`. Size-scoped sets keep their prefix (`--lg-primary-*`, `--lg-inline-*`) because they sit on a separate axis.

Keep the **category prefix** — it prevents collisions, not the role (`Card/card-surface-…` vs `Block/block-surface-color` differ only by group). House convention: the Figma leaf mirrors its group path; a leaf that stops echoing its group is a bug. `&` means a combined token (`label-&-stroke`).

## 2. Recipes

**A. Token added to an existing 4-mode collection** — add it to **all four** blocks *and* register it in `@theme inline`.

**B. Single value changed in one mode** — edit that line, then re-run the full verification; a primitive rename can invalidate unrelated tokens.

**C. New collection appears** — two questions decide the mechanism:
1. *Do values differ per mode?* No → single-mode in `:root`; never re-declare under `[data-theme]`. That is the opt-out.
2. *If yes, are the modes brand×surface?* Yes → global 4 modes. No → **parallel theme axis**: own `data-*` attribute, own token prefix.

A parallel axis is not a special mechanism — the same attribute-selector trick as `data-theme` with a disjoint namespace, so both compose on one element. Keep the `data-` prefix for valid HTML; avoid `data-theme` (claimed by next-themes, daisyUI). Two groups sharing one axis need value prefixes (`mc-`, `lg-`); separate attributes remove them.

**D. Renaming a token — a name lives in THREE places:** the declaration in all four mode blocks, the `@theme inline` registration (`--color-x`), and the right-hand side of that registration (`var(--x)`). Change only some and the variable is defined in a subset of modes; the utilities then silently produce nothing in the rest, with no build error. After any rename assert: the old name appears **zero** times, and registration count equals reference count.

**E. Completeness rule — non-negotiable.** Every `[data-theme]` block declares the **full** token set, and the default gets its own selector:

```css
:root, [data-theme="cole-tint-surface-warm"] { /* all tokens */ }
```

Custom properties inherit, so a diff-only block works solely while its parent is the default; nested under another theme it inherits the ancestor values for everything it fails to restate. Without the explicit default selector no subtree can switch back. Applies to every parallel axis. The redundancy is intentional — it makes nesting behave like a Figma mode pin.

## 3. Verify (never skip)

```bash
npm install tailwindcss @tailwindcss/cli
npx @tailwindcss/cli -i app.css -o out.css --content t.html   # t.html lists every expected class
```

1. **Build clean.**
2. **Utilities exist** — grep the output for each expected class; silent tokens mean a wrong namespace.
3. **Completeness first, values second.** Count declarations per block *and* compute the union of token names across blocks. All counts equal **and** equal the union size. A union larger than the per-block count means blocks are missing tokens — the failure mode a value-diff hides, because absent tokens get skipped rather than flagged.
4. **Values** — resolve every token through its full `var()` chain to a final hex and diff against the live Figma dump. Target: zero mismatches, zero unresolved.

## 4. Figma gotchas

- **Stale variable names.** `getVariableByIdAsync` can return a variable old name after a rename, so an alias can look wrong when it is fine. Verify names against the full collection listing, never the getter on an alias target. Values are reliable; names are not.
- **Names can lie about values.** Check resolved px, not the name: a variable called `(48rem)` held 674px. Rule: 1 twuc = 4px, rem = px ÷ 16.
- **Raw hex in a semantic collection** breaks the two-layer model — add primitives and alias to them.
- **Bindings may be instance-level.** Scan for master bindings *and* instance overrides; the same override can be reported at several nesting depths, so rebinding 30 nodes can clear 51 reported hits. Re-scan to confirm zero references remain. `setBoundVariableForPaint` returns a **new** paint — reassign the array.
- **`use_figma` is atomic per script.** In batch mutations wrap each node in its own try/catch.
- **New variables:** set `scopes` explicitly; this library uses `[ALL_SCOPES]` — match it.
- **Page context resets** between calls; call `setCurrentPageAsync` at most once per script and fan multi-page work out in parallel.

## 5. Committing via the GitHub web editor

- **Never read file content from `.cm-line`** — CodeMirror virtualises, so only ~20 visible lines exist in the DOM. Reading them and writing back **truncates the file**. Always fetch current content from the GitHub API, patch the string, then `focus()` → `execCommand(selectAll)` → `execCommand(insertText, …)` on `.cm-content`. If a truncation slips through it is recoverable while uncommitted: re-fetch from the API and redo.
- **The GitHub API caches.** After committing, re-fetch with a cache-buster and `{cache:no-store}` before concluding a commit failed; also check the commits endpoint. `raw.githubusercontent.com` lags minutes.
- Copilot may overwrite a custom commit message — check the result or accept its wording.
- In `javascript_tool`, if the script uses `return` anywhere it is wrapped as a function body and the trailing expression is **not** auto-returned — end with an explicit `return`, or avoid `return` entirely.
- Sanitisation can redact output that looks key-like; return findings as one joined string when a result comes back blocked.
