# 🎨 LEGACY workaround: stylesheet-based style application
**For Figma variable edge cases only — NOT the standard path**

**Status:** LEGACY since the 2026-07-13 correction (see below). Load only for the two edge cases listed here.
**Tested:** 2026-05-31 / 2026-06-02 / 2026-07-13 (correction review)

---

> **Correction 2026-07-13:** the earlier assumption "Figma blocks all variable APIs / variables can't be linked to nodes" was wrong — the cause was a bug in the test code (ID format `'4146:39881'` instead of `'VariableID:4146:39881'`), not a platform restriction. Reading, writing, creating variables and adding/removing modes all work regularly via `use_figma` — details and code patterns: `1.3-figma-api-reference.md` §2️⃣.
>
> This workaround remains useful for exactly **two edge cases** where the direct variable API doesn't apply:
> 1. A text layer is **not yet** bound to a variable (free text) — `setBoundVariable()` can't be used, so values must be set manually before a variable link makes sense.
> 2. Text styles that come from a connected **library** (`figma.getLocalTextStylesAsync()` returns empty arrays for those) — see "Library text styles via textStyleId" below.
>
> Note: Claude can also create **local** text styles directly (`figma.createTextStyle()`, verified 2026-07-20 — see `1.3-figma-api-reference.md` §1️⃣); this workaround is not needed for those.

## Edge case 1: stylesheet frame as value source (free text, no variable binding)

**Idea:** the user creates a "DESIGN_TOKENS" stylesheet frame in Figma and shares a screenshot; Claude reads the values and sets them DIRECTLY on the new elements; the user (or Claude, if a target variable already exists) links variables afterwards.

**Stylesheet frame contents** — clear names, visible hex/RGB values, all properties documented (font, size, weight, line-height), optional variable-name references:

```
┌─────────────────────────────────────────┐
│ DESIGN TOKENS / STYLESHEET              │
├─────────────────────────────────────────┤
│ COLORS:                                 │
│ ▰ Primary Blue   #3366CC  [BlueSky]     │
│ ▰ Success Green  #00AA44  [Success]     │
│ TYPOGRAPHY:                             │
│ H1: Inter Bold 24px, line-height 130%   │
│ Body: Inter Regular 14px, line-height 150% │
│ SPACING:                                │
│ Large (32px), Medium (16px), Small (8px)│
└─────────────────────────────────────────┘
```

**Claude parses the screenshot into a token object and creates elements from it:**

```javascript
const designTokens = {
  colors: { primaryBlue: { hex: '#3366CC', rgb: { r: 0.2, g: 0.4, b: 0.8 }, variable: 'BlueSky' } },
  typography: {
    headingL: { family: 'Inter', style: 'Bold', size: 24, lineHeight: { value: 130, unit: 'PERCENT' }, variable: 'HeadingL' },
    body:     { family: 'Inter', style: 'Regular', size: 14, lineHeight: { value: 150, unit: 'PERCENT' }, variable: 'Body' }
  },
  spacing: { large: { value: 32, variable: 'Spacing-L' }, medium: { value: 16, variable: 'Spacing-M' }, small: { value: 8, variable: 'Spacing-S' } }
};

async function createHeadingWithToken(text, tokenName = 'headingL') {
  const heading = figma.createText();
  heading.characters = text;
  const token = designTokens.typography[tokenName];
  await figma.loadFontAsync({ family: token.family, style: token.style });
  heading.fontSize = token.size;
  heading.lineHeight = token.lineHeight;
  heading.fills = [{ type: 'SOLID', color: designTokens.colors.primaryBlue.rgb }];
  return heading;
}
```

**Afterwards:** the user links the elements to variables manually in Figma — or Claude binds directly via the variable API if the target variable already exists (`1.3-figma-api-reference.md`).

**Checklist:** all values read from the stylesheet · fonts loaded before setting text · ALL properties set (not just size) · consistent across elements · user verifies visually.

## Edge case 2: transfer library text styles via textStyleId

**Problem:** `figma.getLocalTextStylesAsync()` returns empty arrays for styles that come from a connected library (not locally defined).

**Solution:** read the style ID from one already-linked node and apply it to all matching nodes. **Precondition:** the user applies the desired style manually to one node once.

```javascript
// Step 1: find nodes that already carry a style ID (one must be linked already)
const allText = page.findAllWithCriteria({ types: ["TEXT"] });
const withStyle = allText.filter(n => n.textStyleId && n.textStyleId !== "");

// Step 2: identify the ID (e.g. filter by font family/size)
const styleId = withStyle.find(n =>
  n.fontName.family === "Hanken Grotesk" && n.fontSize === 9
)?.textStyleId;

// Step 3: apply the style to all matching nodes
const targets = allText.filter(n =>
  n.fontName !== figma.mixed &&
  n.fontName.family === "Hanken Grotesk" &&
  n.fontName.style === "Regular" &&
  n.fontSize === 9
);
for (const node of targets) {
  node.textStyleId = styleId;
}
```

**Result:** all matching text nodes are linked to the library style — no manual per-node selection.
