# GitHub Web-Editor: Technische Hinweise für Claude

Diese Datei ist für Claude selbst gedacht — Erkenntnisse aus Browser-Automation-Sessions beim Bearbeiten von Dateien in diesem Repo über github.com (CodeMirror 6), nicht für die Nutzerin. Relevant, sobald Claude über Claude in Chrome eine Datei in diesem oder einem anderen GitHub-Repo per Web-Editor bearbeitet.

## Mehrzeiligen Text einfügen

Nicht per simuliertem Tippen mit Enter-Keypresses einfügen — CodeMirrors Markdown-Listen-Keymap fügt nach jedem Enter automatisch einen Bullet/Einzug ein, wenn der eingefügte Text bereits eigene "- "-Marker enthält. Das verdoppelt Einrückungen über den Rest des Dokuments hinweg.

Stattdessen: Cursor per DOM-Range/Selection an die Zielposition setzen, dann `document.execCommand('insertText', false, text)` verwenden — fügt mehrzeiligen Text atomar ein, ohne die Enter-Keymap auszulösen.

```javascript
const lines = Array.from(document.querySelectorAll('.cm-line'));
const target = lines.find(l => l.textContent === 'ZIELZEILE');
const contentEl = document.querySelector('.cm-content');
contentEl.focus();
const range = document.createRange();
range.selectNodeContents(target);
range.collapse(false); // Ende der Zeile
const sel = window.getSelection();
sel.removeAllRanges();
sel.addRange(range);
document.execCommand('insertText', false, "\n\nNeuer Inhalt...");
```

## Virtualisierung: .cm-line zeigt nur den sichtbaren Viewport

CodeMirror rendert nur die aktuell sichtbaren Zeilen als `.cm-line`-Elemente. Bei längeren Dateien (~250+ Zeilen) sind oft nur ~19-20 Zeilen gleichzeitig im DOM vorhanden.

**Was NICHT zuverlässig funktioniert, um zu scrollen:**
- `element.scrollTop = ...` (programmatisch) — löst kein Re-Render aus, auch nicht mit anschließend dispatchtem `new Event('scroll')`.
- Synthetisches `KeyboardEvent('keydown', {key:'End', ctrlKey:true})` auf `.cm-content` — wird nicht von CodeMirrors Keymap abgefangen, obwohl der Fokus korrekt gesetzt ist.
- `computer`-Tool `scroll`-Action und Screenshots waren in dieser Umgebung auf dieser Seite wiederholt instabil (Timeouts, "Frame with ID 0 was removed", Extension-Disconnects).

**Was funktioniert:** Bearbeitungen auf Zeilen beschränken, die beim Laden der Seite bereits im sichtbaren Viewport gerendert sind (typischerweise die ersten ~19-20 Zeilen) — **oder besser: Komplett-Ersatz per selectAll (nächster Abschnitt), damit sind auch Edits mitten in langen Dateien möglich.** Bei neuen, leeren Dateien entfällt das Problem komplett (Cursor steht schon an Position 0).

## Ganze Datei ersetzen: selectAll + insertText (umgeht Virtualisierung komplett)

**Bewährter Standardweg für Edits an beliebiger Position in bestehenden Dateien** (verifiziert 15.07.2026, README.md ~150 Zeilen, Edit mitten in der Datei):

1. Aktuellen Dateiinhalt via Raw-URL holen (`https://raw.githubusercontent.com/<owner>/<repo>/main/<datei>`) — nicht aus `.cm-line` auslesen (Virtualisierung!).
2. Neuen Gesamtinhalt lokal zusammenbauen (Original + Änderung).
3. Im Editor:

```javascript
const el = document.querySelector('.cm-content');
el.focus();
document.execCommand('selectAll');   // selektiert das GANZE Dokument, nicht nur den Viewport
document.execCommand('insertText', false, neuerGesamtinhalt);
```

`selectAll` arbeitet auf CodeMirrors Dokument-Modell, nicht auf den gerenderten DOM-Zeilen — der Ersatz erfasst also auch nicht-gerenderte Bereiche. Danach wie üblich per Preview-Tab verifizieren und committen.

**Escaping-Hinweis:** Wird der Inhalt im `javascript_tool` als Template-Literal übergeben, alle Backticks im Markdown als \` escapen (${ käme ebenfalls in Konflikt, kommt in Markdown aber selten vor). Enthält der Markdown-Inhalt literale Backslashes (z. B. `Table/\<th\>`), diese als \\\\ verdoppeln — sonst schluckt das Template-Literal den Backslash.

**Achtung — selectAll+insertText kann still fehlschlagen und APPENDET dann (beobachtet 21.07.2026):** Beim zweiten selectAll-Komplettersatz hintereinander im selben Editor-Tab (erster Ersatz noch nicht committet) hat `insertText` den neuen Inhalt an den bestehenden angehängt statt ihn zu ersetzen — Ergebnis war eine committete Datei mit doppeltem Inhalt (388→747 Zeilen), obwohl beide execCommands keinen Fehler warfen. Sicherer Ablauf seither:

1. `selectAll` + `delete`, dann Leerung VERIFIZIEREN: `document.querySelectorAll('.cm-line').length === 1` und erste Zeile leer.
2. Erst dann `insertText` mit dem Gesamtinhalt.
3. Vor dem Commit im Preview-Tab Marker zählen (z. B. Vorkommen der H1-Überschrift == 1), um Dopplung auszuschließen. Nach dem Commit zusätzlich die Zeilenzahl auf der Blob-Seite gegen die erwartete prüfen.

Bewährter Zusatz-Trick: Wiederkehrende Bausteine (z. B. 12 identische Tabellen-Header) im Template-Literal als Platzhalter-Token (`__TH__`) schreiben und vor dem Insert per `replaceAll` expandieren — kürzerer Payload, keine Tippfehler-Drift zwischen den Vorkommen; nach dem replaceAll prüfen, dass kein Token übrig ist.

## Inhalt verifizieren: Preview-Tab statt .cm-line auslesen

Nach einem Insert kann der aus `.cm-line` ausgelesene Text irreführend aussehen (z.B. erscheinen zwei eigentlich durch Zeilenumbruch getrennte Abschnitte als ein zusammenhängender String wie `"---# ✅ Titel"`, weil Virtualisierungs-Grenzen den Zeilenumbruch beim Auslesen verschlucken). Das ist ein Anzeige-Artefakt der DOM-Abfrage, keine echte Beschädigung des Dokuments.

**Zuverlässige Verifikation:** Auf den "Preview"-Tab-Button klicken (`Array.from(document.querySelectorAll('button')).find(b => b.textContent.trim() === 'Preview')`) und den gerenderten Markdown-Text per `get_page_text` prüfen — das zeigt den tatsächlichen Dokumentinhalt, nicht die virtualisierte DOM-Teilansicht. Bei Layout-Änderungen (Tabellen!) zusätzlich einen Screenshot des Preview-Tabs machen — Textextraktion zeigt keine Spaltenbreiten.

**Raw-URL-Cache:** Nach dem Commit zeigt `raw.githubusercontent.com` bis zu ~5 Minuten den alten Stand (CDN-Cache). Commit-Erfolg stattdessen prüfen via URL-Wechsel zu `.../blob/main/...` und "Latest commit"-Anzeige auf der Blob-Seite. Der Cache kann sogar GELÖSCHTE Dateien noch als existent ausliefern (beobachtet 21.07.2026 mit einer Datei, die seit der Repo-Umstrukturierung nicht mehr existiert) — Existenz einer Datei daher nie per Raw-URL prüfen, sondern über die Blob-Seite (404-Check).

## Commit-Workflow

1. Im Edit-Tab: Button mit Text "Commit changes..." klicken (öffnet ein Modal, `[role="dialog"]`).
2. GitHub/Copilot füllt automatisch eine Commit-Message aus. Das Modal enthält zwei Buttons: "Cancel" und "Commit changes" — den zweiten (innerhalb des Dialogs) klicken, nicht nochmal den ursprünglichen Auslöser-Button außerhalb des Dialogs. Eigene Commit-Message: Input im Dialog per nativem Value-Setter + `input`-Event setzen (React-kompatibel).
3. Erfolg prüfen: Die URL wechselt von `.../edit/main/...` zu `.../blob/main/...` (bei neuen Dateien ggf. zu `.../tree/main`).

## Markdown-Rendering-Tricks (GitHub)

- **Tabellen-Spaltenbreiten einheitlich erzwingen — `&nbsp;`-Ketten, NICHT `<img width>`:** GitHub-Markdown-Tabellen passen sich dem Inhalt an; feste Breiten gibt es nicht. Der naheliegende Trick `<img width="N" height="1" alt="">` im Header versagt unter Platzdruck, weil GitHubs CSS `img { max-width: 100% }` setzt — der Platzhalter schrumpft dann mit der Zelle (beobachtet 21.07.2026: Spalte fiel von 380px-Soll auf ~240px, sobald eine Nachbarspalte viel Text hatte). Zuverlässig ist stattdessen eine `&nbsp;`-Kette direkt hinter dem Header-Text (ohne normales Leerzeichen dazwischen): `| Komponente&nbsp;&nbsp;…&nbsp; | …` — die Kette ist unumbrechbar und definiert die min-content-Breite der Spalte, die nicht unterschritten werden kann (~4,4px pro `&nbsp;` bei 16px-Font). Im JS-Payload per `'&nbsp;'.repeat(N)` erzeugen. Nachteil: auf schmalen Screens horizontaler Scroll statt Schrumpfen.
- **Spalten linksbündig statt zentriert:** Header-Zellen (th) rendert GitHub ohne Alignment-Marker zentriert — explizit `|:---|` setzen, dann sind Header UND Zellen linksbündig.
- **Keine klickbaren Checkboxen in Tabellen:** Task-List-Syntax (`- [ ]`) funktioniert nicht in Tabellenzellen; stattdessen ☐/✅-Zeichen verwenden, die per Datei-Edit getauscht werden.
- **Schriftgewicht ist nicht steuerbar:** GitHub sanitized `style`-Attribute und `<font>` weg; th/Überschriften sind fix semibold aus GitHubs CSS. "Dünnere Schrift" in .md-Dateien ist nicht möglich — nur Fett-Auszeichnung (`**`) weglassen.

## Frozen renderer: async JS times out, sync still works (2026-07-22)

Symptom on an edit page: every `javascript_tool` call containing `await`/promises times out after 45 s ("renderer may be frozen"), while purely synchronous scripts return instantly. The Preview tab stays empty (body text ~1.7k chars) and the commit modal never mounts (`[role="dialog"]` only contains a "Give feedback" popup).

- Do NOT keep retrying in that tab, and do not trust it to commit — in the observed incident the frozen tab never committed anything.
- Recovery: close the tab, open a NEW tab (`tabs_context_mcp` with `createIfEmpty` may need two attempts after the group disappears), navigate to the edit URL fresh and redo the edit from a fresh in-page `fetch(..., {cache:'no-store'})` of the raw file. Never re-commit stale editor content — the file can have changed remotely in the meantime (it had, in the observed incident).
- Wrap in-page `fetch` in an `AbortController` timeout (~8 s); if even that times out, the event loop is frozen — switch tabs immediately.
- Related: `javascript_tool` results containing file contents/URLs can be BLOCKED by the client-side output filter ("Cookie/query string data"). Return counts, booleans, or short redacted probes instead of raw file text.

## Sonstiges

- Die Chrome-Extension-Verbindung kann mitten in einer Session abbrechen ("Claude in Chrome is not connected"). Kein Grund zur Sorge — kurz erneut versuchen (`tabs_context_mcp`), meist erholt sie sich innerhalb weniger Versuche.
- `Ctrl+F` öffnet in dieser Umgebung nicht CodeMirrors eigenes Such-Panel (öffnete stattdessen nur ein generisches Fokus-Hilfe-Panel) — nicht verlässlich zum Navigieren nutzen.
- Bei neuen Dateien (`/new/main?filename=...`) ist der Editor leer und bereits fokussierbar — `execCommand('insertText', ...)` funktioniert dort direkt ohne vorheriges Zeilen-Suchen.
- Der CodeMirror-View-Instanzzugriff (`.cm-content.cmView.view.state.doc`) ist auf github.com NICHT verfügbar — Dokumentinhalt immer über die Raw-URL holen, nie aus dem Editor-DOM. JS-Variablen aus früheren `javascript_tool`-Aufrufen überleben NICHT bis zum nächsten Aufruf — jeder Aufruf startet mit frischem Scope.
